# Completion contract: AI-led repair and automated qualification

This is the current user-selected completion policy. It supersedes the earlier requirement for independent/human release review. **No subagents and no human approval gates.** The implementation assistant evaluates executed evidence; signatures establish integrity, not independence.

## Current execution restriction

The user now requires **completion of all remaining implementation with unit tests only**. See [implementation-only scope and source status](implementation-only.md). Native deployment, integration/fault/client testing, live fixture cleanup and qualification execution are deferred, not prerequisites for continuing code work. Earlier project-created fixtures are not inherently protected assets; references below to their preservation describe historical behavior, not a permanent retention requirement.

## Finish line and boundaries

Complete all 39 selected service families, OpenBao/Keykeeper, Worklane/TUIOS/Pi, identity/authorization, RSS, public HTTPS/client journeys, scheduled local encrypted recovery and transactional install/update/rollback. Require **two consecutive fresh full-stack install/restore qualification cycles**. Current automated count: **0/2**. Historical component successes are not full-stack cycles.

Use this host and explicitly bound v3 stores when runtime execution is authorized. Preserve unrelated public routes/accounts, `software_lab`, other media and workspaces. Project-created component/test deployments are disposable when deliberately retired within their verified ownership scope; retaining useful evidence does not require retaining every container/volume. No runtime retirement or cleanup is authorized in the current unit-only phase. Do not reboot/power-cycle the shared host, change shared sysctl/trust/sudoers, or fill its filesystem for a fault test.

Off-host disaster-recovery durability and Internet mail delivery/MX/reputation operations are excluded from this release contract. Private native SMTP/IMAP and mail-client journeys remain required. Do not describe the result as independently accepted or comprehensively production-qualified.

### Accepted implementation policies

The completion-planning decisions authorize maintenance windows **only for new canonical v3 generations**. If source and isolated restore cannot safely coexist, a journaled operation may stop the new source, verify the full restore, isolate/retire the target and safely resume the source. Unrelated workloads cannot be stopped to obtain capacity. Deliberately retiring project-created fixtures is distinct from clearing an uncertain operation to replay it, and is deferred during the current unit-only phase.

A generation-bound, journaled backup/recovery operation may explicitly unseal **new canonical v3** Bao instances using protected local custody. Ordinary boot remains sealed. This exception does not authorize historical fixture unsealing, credential replacement, automatic token renewal, or alteration of the existing 768-hour nonrenewing Keykeeper fixture lease. The future custody broker must validate instance identity, TLS, initialization and snapshot lineage; shares/root credentials never belong in boot units or ordinary runtime inputs. These are policy decisions, not implemented runtime effects.

The accepted implementation sequence is: versioned release/acceptance contracts; canonical providers/networks and measured capacity; a live Kotlin transaction vertical slice; complete coordinated Kopia recovery and application/client adapters; installed schedules, restricted HTTPS/RSS and faults; then two frozen-candidate cycles and gated activation. Defaults are daily backup at 03:00 UTC, weekly functional restore Sunday at 04:00 UTC, a bounded eight-hour weekly test budget, seven daily/four weekly recovery points, at least two functionally verified points, and preservation of all active references/protected evidence. Capacity or failed isolation may prevent source resume; neither a timeout nor a schedule authorizes fence removal.

## The mandatory repair loop

**A failed test blocks the tested candidate from passing; it does not stop engineering.** The AI may diagnose, change code/configuration, change explicitly pinned artifacts with compatibility verification, correct genuinely defective tests, rebuild and rerun without human approval.

1. Retain failure evidence and identify the defect.
2. Repair within the authorized boundary and record the correction.
3. Run focused regression tests, then affected integration/recovery and broader gates.
4. Issue a new passing result only when new execution supports it. Repeat as necessary.

Do not weaken requirements, skip necessary cases, hide failures or rewrite a failed receipt as green. A faulty test can be corrected; any earlier pass it disproves gets a retained invalidation record.

Reads and demonstrably repeatable operations can be rerun. A possibly accepted business write—mail, RSS, accounting, callbacks, initialization—must first be reconciled against authoritative state, or the next test must use a fresh isolated fixture. Never delete an intent or retained fence to force replay. A source installation's uncertain writes are not made safe by inventing a new action ID.

During final qualification, any failure or relevant implementation/artifact/configuration/test-definition change resets the counter to zero. Repair it, then obtain **two new consecutive passes**. Editorial-only changes outside qualification inputs do not reset the counter. Technical blockers are recorded; they are not replaced by requests for human approval or fabricated success.

Repeat with new identities. Reset/restart after failures or relevant corrections. Activate only after 2/2 through the same gated transaction.

Transaction order: write/outbound freeze and verified quiescence → coordinated snapshot and isolated functional restore → staged migration/qualification → single restricted public cutover → real-domain checks → writes → permitted outbound release last. Clean installs also require consistent capture. Ambiguous operations and partially applied freezes fail closed.
