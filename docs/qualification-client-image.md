# Fixed browser/Android qualification client image — acquisition and runtime recipe

**Current authority: [rapid completion](rapid-completion.md).** Necessary artifact acquisition,
installation, image builds and bounded execution through qualification are authorized; the
former source-only execution ban is superseded. Authentic provenance, independent trust
anchors and runtime confinement still apply. A candidate without a verified acquired
`qualification-client` linux/amd64 OCI image is **not qualified**. This recipe does not
establish an image digest, official APK signer, successful guest run or functional TURN.
Qualification remains **0/2**.

## Exact external source/acquisition prerequisites

1. Independently acquire a reviewed Linux amd64 toolchain OCI base by immutable **manifest** digest; verify image ID, source repository, all repo digests, architecture and OS in the existing `AcquiredInventory`/private Podman store. Never accept a tag, `latest`, automatic image pull, or image acquired merely because a tool path exists. The base must contain real pinned Python 3.11+ (for `hashlib.file_digest`), Chromium and scoped NSS `certutil`, Java 21 `java`/`keytool`, `/usr/sbin/nft` on the host, Android `adb`, `apksigner`, emulator plus Google APIs x86_64 API34 and API36 **official** system images. Source/review each binary and Android SDK platform repository manifest and transitive tool artifact hashes; compare signed release provenance from upstream. No runtime installer, network fetching or generic trust-root injection in the image recipe.
2. Supply two clean independently named owned AVDs for each API level: `p0v3-api34`, `p0v3-api34-reader`, `p0v3-api36`, `p0v3-api36-reader`. Each is created from its matching acquired system image; QClient starts these with `-wipe-data`, distinct pinned host TCP pairs, and `-dns-server 127.0.0.1` against a QClient-local exact-host resolver. The host must expose authorized `/dev/kvm` device mapping, an **owned** emulator group permission and compatible kernel/netfilter. Missing prerequisites fail closed; there is no software-emulation fallback or device reuse.
3. Obtain each official Android app APK through its authoritative publisher, independently verify APK SHA-256 **and the single apksigner signer digest** against the reviewed `acceptance/cases/android-apps.json`; mount only that bounded file read-only from `/mnt/media/p0-v3/qualified-clients/...`. Empty/unreviewed pins are not filled with guesses or a substitute APK. The controller also requires actual guest installation identity/readback before the official UI is exercised.
4. Supply verified tool+AVD image artifact hashes as the explicit non-default build args in `platform/src/main/resources/runtime/qualified-client.Containerfile`; independently hash `qualified-client-entry.py` before the image build authorized by rapid completion. The image recipe has no runtime `apt`, `curl`, installer or arbitrary source clone. Inspect final immutable manifest digest and image ID *after* build, add one reviewed product `qualification-client` to the externally acquired candidate inventory, and bind the actual digest and tool manifest to the release candidate. Acquisition/build receipts establish actual artifacts, not a qualification pass.

5. For the sole Seafile HEADLESS/NATIVE official two-device client, source **real haiwen/seafile v9.0.15** `seaf-cli`, `seaf-daemon`, `seafile.rpcclient`, `pysearpc` and complete native ELF/DT_NEEDED/Python module closure through an independently verified signed producer receipt. Root-owned immutable image paths are pinned in `NativeSeafileToolPins`; `QualificationClientRuntime.real(...,reviewedSeafileProducerPublicKeySha256)` defaults to null and FAILS CLOSED absent an independently reviewed public-key hash (do not copy it from the request). Require an authoritative independently reviewed **Ed25519** producer public key and detached raw signature over the exact closure JSON (not an arbitrary new self-signed request key). Pin that public key, signed closure JSON, signature, actual `/usr/bin/openssl` and each binary/module hash; runtime verifies the signature with that key, root ownership, nonwritable modes, per-file 256 MiB and aggregate 1 GiB and exact full listed Python module tree. Unknown producer signer/signature or acquired final OCI manifest/image ID is an external prerequisite, not a synthetic `signed=true` assertion. `qualified-client.Containerfile` contains SHA build ARGs only, no installer or acquisition.

## Runtime authority and isolation

`QualificationClientRuntime.real(generationRoot,spec,fingerprint,reviewedInventory,approvedHosts)` consumes only a sealed generation, exact network `qualification-web`, live Caddy+LiveKit interface readbacks, independently pinned case intent/context/suite/adapter/source observation/CA/APK, and capacity reservation (8 GiB maximum client memory, 8 GiB maximum scratch, bounded PIDs, platform headroom 16 GiB/10 GiB). It starts exactly one pinned image with no host port, host network, privilege, upstream key, image pull or arbitrary command. Its fixed Python entrypoint first runs only a loopback exact-approved-host DNS responder and waits for a short one-use generation-owned gate. The controller journals a fixed per-QClient nft rule scope before changing **that verified container namespace**, then native-readbacks CID/PID/netns/Caddy and LiveKit /32. All external QClient egress except Caddy:443 and exact TURN ports to LiveKit:3478/5349 is denied; direct SFU TCP7880/UDP50000–50020 has explicit counters/drop. It does not write host-global DNS, certificate roots or unrelated nft tables.

Fresh INSTALL uses `QualificationInstallIngress` on the same Caddy instance's client-only IP and **same managed public ACME certificate**; RESTORE stops the original source and uses `RestrictedRestoreBridge` with original certificate+key/Host/SNI, no cookie authority. The controller must audit two independent original owner/reader guest processes when LiveKit Android uses two official Element X peers, and A07 guest-only iptables/conntrack/packet proof is distinct from A13's **outer** QEMU netns proof. The fixed Seafile gate additionally binds the native CID/PID/netns/image, original `files.datamancy.net` CA/leaf/Caddy IP, native nft readback, full signed client tool pins and fresh born-only `/case/sync-device-a`/`sync-device-b` roots; ordinary clients retain their four-field historical gate. Official Android against source/restored original public ACME identities uses ordinary system WebPKI; a host NSS/Java receipt is never an Android guest trust proof. The separate A11 Alloy/Loki `NATIVE_NETWORK_DENIAL` QClient is a real bounded QClient netns child denied socket against exact Loki:3100 with native nft counter readback; it does not run a fake HTTP client or host-native adapter. The retained qualification owner must start/admit it before the actual host-private adapter and fence it afterward. Native results and original INSTALL artifacts must be read back by acceptance, never inferred from an image exit status. After the journey, the native QClient and guest namespace are fenced before Caddy private bridge removal, target isolation, `BridgeResumeProof`, and source resume.

**Remaining runtime integration (direct implementation, not worker assignments):** stage reviewed image and immutable tool artifacts, bind verified one-use phase/case requests and generation capacities, mount original INSTALL oracle read-only at the same absolute path, wire QClient gate/guest receipt and private CA adoption evidence, install exact source/restored Caddy client listeners, complete Android guest policy/source-state checks, observe externally returned public TURN packets, and use the typed stop+source-resume proofs in whole-phase results. Do not substitute callback booleans, synthetic clients, third-party trust, guessed port forwards, or acceptance host sockets.
