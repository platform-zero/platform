# Handoff to integration owner — decisions and missing inputs

Read the [rendered 89-ID / 46-module matrix](MATRIX_TABLE.md) and [evidence/limits](STAGES.md). This is research and proposed acceptance criteria, **not** installation, runtime verification or route approval. **2/2 remains 0.** No changes outside `research/`.

## Blockers to a deployable contract

1. **Authorize hostnames and access policies:** approve/reject each proposed `*.datamancy.net` route; choose actual apex/portal and mail host; confirm DNS authority, TLS issuer, internal-only vs public exposure, reverse-proxy path/upgrade rules, identity provider and session/logout policy. Approve immutable identifiers **before creating data**: Synapse `server_name` / federation / `.well-known`, Mastodon federation domain, MAS issuer/redirect URIs, Keycloak issuer; LiveKit WSS/TURN domain, UDP/TCP firewall and external IP; mail MX, SPF, DKIM, DMARC and port policy. Do not turn API/backend/helper IDs into public homepages.
2. **Supply a per-ID implementation contract:** image/repository, pinned tag and digest, architecture, version, command/entrypoint, run mode (long-running/one-shot/periodic/build), health signal, UID/GID, permissions, upstream release notes, config templates and dependency ordering. Especially ambiguous: `erpnext` umbrella vs backend/frontend (no explicitly named ERPNext frontend), `kopia` server vs CLI, `mailserver` actual distribution, `matrix-rtc-auth` actual image vs upstream lk-jwt-service, `huly-kvs`, `onboarding`, `portal`, `firefly-identity-check`, `firefly-native-api`, `*-sso`, all `*-bootstrap`/`*-init`/`*-configure`, RSS automation and all test runners. Huly *development* compose and old P0 code are not a production design authority.
3. **Provide state ownership map and restore runbooks:** actual mount points/DB assignments, secrets location, encryption/signing key custody and rotation; application-consistent snapshots including DB+media/objects/queues as applicable; Kopia repo backend **off-host** and separate failure domain, encryption recovery password and retention/immutability, monitoring and restore frequency. Decide whether Loki/Prometheus/OpenSearch/Huly search/Redis/Valkey data is canonical or disposable; supply restore RPO/RTO, verify isolated restore with checksums/user scenarios. Firefly's export is **not** backup per upstream guidance. Backup claims require both a completed snapshot and an isolated successful restore; do not label UI data export as disaster recovery.
4. **Prove client paths, not just available apps:** decide supported Android products/versions, official package IDs and publisher/signing identities from current release metadata (no APK recommendation from name alone), endpoint compatibility for Element/MatrixRTC and MAS, ntfy self-hosted delivery/battery behavior, Home Assistant remote access, Seafile/Jellyfin clients. Browser fallback is not an official native app.
5. **Supply test and business policy inputs:** isolated test credentials, authorized test devices/data, desired success criteria for real account actions in matrix; allowlisted torrent/media content and feed ownership, mail external deliverability domain, backup destination budget, approvals for federation/internet exposure, audit log retention and vulnerability/upgrade policy. Confirm test-runner images/API levels, how artifacts are collected, and whether emulator instances persist.

An initial Seafile docs hostname failed TLS, but the current manual and vendor downloads page were retrieved: Android package `com.seafile.seadroid2` is vendor-listed; compatibility with the chosen server release is **not** verified. Several links in the matrix are *entry points* only; verify installation and backup recipes for exact chosen releases before implementation.
- Get repository/specs for all **local-only** helpers and custom APIs, not just their evocative names. `services.json` gives authoritative IDs/grouping **only**; it cannot establish what command executes or where data lives.
- Verify exact route rules (especially Matrix `.well-known`, MAS OAuth, Huly websocket, ONLYOFFICE document callback, ERPNext socket.io, and Mastodon federation) with upstream versioned docs and integration tests before declaring a hostname operational.

**Suggested acceptance record for each product:** source URL + selected version/digest; approved hostname and access class; exact command, dependency and health check; backup set plus encrypted off-host artifact ID; isolated restore result with expected user action and timestamp; Android provenance/compatibility if promised. Do not advance the 2/2 counter from this research alone.
